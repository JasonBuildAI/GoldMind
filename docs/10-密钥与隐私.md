# 密钥与隐私

本文件记录本仓库的密钥/隐私处理规则、**已发生的一次泄漏**，以及尚未完成的操作。

---

## 一、规则

1. 密钥只进 `.env` 与部署环境。`backend/.env` 已被 `.gitignore` 忽略；
   `.env.example` 只放占位符。
2. 密钥永不进 commit、永不进日志、永不进对话记录或 issue。
3. 新增配置项时先确认它不会写进受版本控制的文件。
4. 需要示例值时用 `your_xxx_here` 这类明显占位符，不要用真实值截断。

## 三、重写历史的标准步骤

> 执行前先备份；执行后需要 force-push，所有协作者的本地克隆都会失效。

```bash
# 0. 先留一条可回退的备份分支
git branch backup/pre-secret-scrub

# 1. 抹掉历史中的字符串（key 与个人联系方式）
#    需要 git-filter-repo：pip install git-filter-repo
#
#    三个占位符都要换成真实值。取值方式（这两条命令只打印，不写文件）：
#      git log -p b8f2842 -- backend/scripts/utils/init_project.py | grep -o 'sk-[A-Za-z0-9]*'
#      git log --all -p | grep -oE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' | sort -u
#      git log --all -p | grep -oE '\b1[0-9]{9}\b' | sort -u        # QQ 号
cat > /tmp/scrub.txt <<'EOF'
<LEAKED_KEY>==>REDACTED
<PERSONAL_GMAIL>==>noreply@example.com
<PERSONAL_QQ_EMAIL>==>noreply@example.com
<PERSONAL_QQ_NUMBER>==>REDACTED
EOF
git filter-repo --replace-text /tmp/scrub.txt

# 1b. 作者/提交者邮箱也在每个 commit 的元数据里，--replace-text 处理不了，
#     要用 --mail-map 单独改：
git log --all --format='%ae' | sort -u    # 先看清有哪些
cat > /tmp/mailmap.txt <<'EOF'
<PERSONAL_GMAIL> <PERSONAL_GMAIL> <noreply@users.noreply.github.com>
EOF
git filter-repo --mail-map /tmp/mailmap.txt

# 或者用内置的 filter-branch（慢，且官方已不推荐）
# git filter-branch --force --index-filter \
#   "git rm --cached --ignore-unmatch backend/scripts/utils/init_project.py" \
#   --prune-empty --tag-name-filter cat -- --all

# 2. 清理 reflog 与不可达对象
git reflog expire --expire=now --all
git gc --prune=now --aggressive

# 3. 验证历史里已经搜不到（前缀用于检索，本身不构成可用凭证）
git log -p --all | grep -c 'sk-d655427b'              # 期望 0
git log --all --format='%ae %ce' | sort -u            # 期望看不到个人邮箱
git log --all -p | grep -cE '[A-Za-z0-9._%+-]+@(gmail|qq)\.com'   # 期望 0

# 4. 推送（会改写远端历史，需协调所有协作者）
git push --force-with-lease origin main
git push --force-with-lease origin --tags
```

**注意**：
- `v1.0.0` 标签也指向旧历史，force-push 标签前请确认是否要保留该版本。
- `git filter-repo` 默认会删掉 `origin` 远端配置，推之前需要 `git remote add` 加回来。
- 上面第 3 步用的 `sk-d655427b` 是 8 位前缀 —— 用来检索是安全的。
- 清完历史后，`backend/tests/unit/test_no_secrets_in_repo.py` 会自动守住工作区，
  但它**看不到历史**；历史只能靠上面这几步。
