## 一、这是什么

GoldMind 是一个**面向个人投资者的黄金市场分析看板**：自动抓取金价与美元指数，
用大语言模型生成多空因子、机构观点、投资建议与市场总结，最后以单页看板呈现。

它**不是**交易系统，不接券商，不下单，不托管资金。

### 给谁用

个人投资者，尤其是希望「打开一个页面就能看到当天黄金市场发生了什么、
有哪些多空理由」的人。

### 一句话判据

> 打开首页，不点任何按钮，就能看到**当天**的金价、美元指数、
> 以及一份基于**当天**新闻生成的多空分析 —— 且当数据源不可用时，
> 页面**明确说明**而不是拿示例数据冒充分析结果。

## 二、现状（已实现）

| 能力 | 说明 |
|------|------|
| 金价与美元指数采集 | 腾讯财经实时金价；新浪财经 ICE 美元指数；历史数据回填支持新浪/东方财富/Yahoo 三源；每个价格附 `basis`（实时报价 / 日收盘 / 量化基准）、来源与 as-of；同一交易日的实时报价与收盘偏差 > 3% 会在数据体检里点名（2.0.2 第 1、2 条） |
| 历史数据存储 | 默认 SQLite 单文件（`backend/goldmind.db`），`gold_prices` / `dollar_index` 两表；`DATABASE_URL` 可选切 MySQL（未随本仓库实测） |
| 多空因子分析 | 基于最近 24 小时新闻（消息板块高权威条目 + RSS，按规范化 URL 去重合并；prompt 给标题 + 清洗截断后的摘要），调用 LLM 生成 5 个看涨 + 5 个看跌因子，带缓存 |
| 机构观点 | 扫描最近 30 天（`INSTITUTION_NEWS_LOOKBACK_DAYS`）新闻 +（联网搜索），整理高盛/瑞银/摩根士丹利/花旗**最近一次可核实**的预测，标注预测日期与来源；空目标价绝不覆盖已有真实记录 |
| 消息板块 | 抓取央行 / 通讯社 / 行业机构 / 专业财经四类高权威来源（默认 13 个实测可用，`NEWS_DIGEST_SOURCES` 可覆盖）的黄金相关消息；按来源权威 / 黄金相关度 / 同题覆盖 / 时效确定性评分（**评分不调用 LLM**），24 小时 / 7 天 / 30 天三个窗口各取前 10 条；可展开看摘要与同题报道、点原文、手动抓取；抓不到就显示「不可用」与原因；这些高权威条目同时进入多空因子 / 机构观点 / 投资建议 / 市场总结的新闻输入（`services/analysis_input.py`） |
| 消息中文化 | 来源池全是英文 RSS，抓取后自动批量译出**中文标题 + 2–3 句中文导语**（一次抓取一次 LLM 调用、只翻尚未翻译的条目，`NEWS_TRANSLATE_ENABLED` / `NEWS_TRANSLATE_BATCH` 可调）；中文只**压缩来源摘要已有的事实**，不许添加原文没有的数字 / 机构 / 背景；译文与英文原文并存存储，页面同时给出、可逐条核对；翻不了时如实显示「中文翻译暂不可用（原因）」，不摆编出来的中文；中文不参与评分、聚类与排序，也不进入任何分析 prompt |
| 投资建议 | 融合市场状态、多空因子、机构观点与最近新闻，生成保守/均衡/机会三档策略 |
| 市场总结 | 输出核心逻辑、主要风险、机构目标价与综合判断 |
| 定时刷新 | APScheduler，价格每日 06:30，新闻与 AI 分析每偶数整点，消息板块每小时第 25 分钟；启动即补跑错过的日期任务，全部任务 `coalesce` + `misfire_grace_time`（2.0.2） |
| 全自动运行（2.0.2） | `backend/.env` 是唯一人工输入：启动引导自动建表 / 迁移 / 回填 / 首轮分析（`AUTO_BOOTSTRAP`），LLM 配置热生效（`CONFIG_WATCH`），每日自动备份（SQLite 保留 7 份）与数据体检（`AUTO_BACKUP`）；`init_db.py` / `backfill_quant.py` / `migrate_*.py` 等脚本降级为可选运维工具，不用也不缺功能 |
| 源可用性看板 | `GET /api/gold/sources/status` 汇总各抓取通道的最近尝试（成功 / 无数据 / 失败 + 原因）；`/health` 暴露引导进度（`bootstrap`）与配置热生效状态（`config_watch`） |
| 量化预测引擎 | 14 个因子覆盖四类影响因素（货币政策与利率 / 避险与信用 / 供需结构 / 市场与技术面），全部来自免费公开数据源，按各自发布节奏自动更新；滚动 z 分数合成得分 → 1 / 5 / 20 / 60 / 250 个交易日（日内～一周 / 1～3 个月 / 6～18 个月）的**一份校准分布**（期望收益 μ、不确定度 σ、上行概率 p = 1 − F̂(−μ/scale)（同一份校准分布的尾部比例）），方向 = sign(μ)、目标价与区间、三情景都由这一份分布派生 —— 因子得分是未校准的输入，「因子偏向（未校准）」折进页面详情只作对照；**每个尺度有自己的主控权重**（短尺度资金流与技术面、中尺度政策预期与美元、长尺度央行购金与需求结构）；走查式回测的命中率评的就是这个方向，并与「永远看多 / 动量 / 抛硬币」对照，未校准得分方向的成绩单独计算、折叠展示。逐源状态（正常 / 未到期 / 不可用）收在折叠的「数据源状态」区，失败也如实标注；可用因子少于 3 个时明说「预测不可用」；1 年尺度按预注册规则**停发方向**（留出期与「永远看多」逐日一致，没有可核实的信息优势），只发布公允价值偏离与年度校准区间 |
| 前端看板 | Vue 3 单页看板（Pinia + Vite，两个 HTML 入口）：报头 + 7 节（今日结论 / 行情 / 驱动 / 消息 / 量化预测 / 投资策略 / 数据与方法）—— 消息是一等板块（`#messages`），不是「驱动」里的小块，30 秒轮询行情（页面隐藏时暂停）；另有独立「研究」页（`app/research.html`）展示预注册候选的留出期评估。视觉语言与组件规范见 `docs/20-前端设计规范.md` |
| 缓存 | 进程内内存 + JSON 文件两级缓存，支持多进程与重启后共享 |

**LLM 供应商**：不写死 —— 任何 OpenAI 兼容端点（OpenAI / DeepSeek / 通义 / Kimi / Ollama /
小米 MiMo 等）都行，由 `backend/.env` 的 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`
三项决定（缺任意一项即「未配置」，各区块如实显示「暂不可用」），
经 `app/services/llm_provider.py` 统一构造。

## 三、目标（尚未实现，不要当成已有能力）

| 能力 | 说明 |
|------|------|
| 多 Agent 协作 / ReAct / RAG | 当前实现是**单轮 prompt 调用**：`llm.invoke(prompt)` → 解析 JSON。没有工具调用循环、没有向量检索、没有 Agent 间通信。早期存在的 `app/agents/` 包从未被实例化，已删除。 |
| 用户系统与个性化 | 无登录、无用户画像，「个性化建议」实为按风险偏好分三档的通用策略。 |
| 移动端 | 无。 |
| 事件条件分布 | 事件标注（FOMC / CPI / NFP / 央行决议 / 央行购金）已用确定性规则落地（不依赖任何日历 API）；但「事件条件下的收益分布」需要免费可核实的宏观日历，2026-10-03 未找到可靠来源，**未落地**。 |
| 联网搜索降级方案 | 见下节限制。 |

## 四、已知限制（必须在 UI 与文档中如实体现）

1. **联网搜索默认关闭**。它用的是 MiMo 插件式的 `web_search` 工具（不是通用 OpenAI
   能力），需要 `LLM_SEARCH_ENABLED=true` 显式开启，且端点侧必须已开通该插件；
   否则端点返回
   `HTTP 400 · web search tool found in the request body, but webSearchEnabled is false`
   （实测，见 `backend/scripts/smoke_llm.py`）。因此「机构观点」在搜索不可用时**只能回退到
   数据库与 RSS 新闻**，不得凭模型印象编造机构目标价。
2. **注意所选端点的用途条款**。接入前先确认供应商条款允许后端调用。示例：小米
   Token Plan 条款限定「仅可在编程工具中使用，禁止用于自定义应用程序后端」，
   以 `tp-` key 作为后端调用属于条款外用法，存在被暂停服务或封禁 key 的风险；
   合规做法是改用按量付费端点（MiMo 为 `https://api.xiaomimimo.com/v1` + `sk-` key）。
   代码侧已有守卫（2026-10-02 起）：`backend/app/services/llm_provider.py` 在构造
   推理 / 搜索客户端时检测该组合，命中会记一条带切换指引的警告（不含密钥本身）；
   `/health` 返回的 `services.ai_config.token_plan_backend` 也会如实标记。
3. **中文与亚洲实物源要实测**。2026-10-03 复验（可复跑 `python scripts/probe_sources.py`）：
   上海黄金交易所 Au99.99 日线（`sge_gold`）可达并已接入，「上海金溢价」从「不可用」
   转为实算；新浪 / 腾讯行情接口可达（实时价与历史回填在用）；金十数据快讯 API（HTTP 502）、
   FX168 RSS（连接成功但 0 条目）、MINING.COM（403）、Kitco（404）不可达，如实记未落地。
   源站会变，结论只对实测日负责。新闻源仍以英文财经媒体为主，可用 `NEWS_RSS_SOURCES` 自行配置。
4. **默认无鉴权，可加可选令牌**。所有接口默认公开可访问，包括会触发付费 LLM 调用的
   `POST .../refresh`；2.0.2 起可设 `REFRESH_TOKEN`，设置后 POST refresh 必须带
   `X-Refresh-Token`。另有 `LLM_DAILY_CALL_BUDGET`（默认 200/日）兜住付费调用预算 ——
   预算用尽时各区块显示「暂不可用 + 原因」，不会编内容。
5. **留出期的长尺度覆盖率仍低于名义值，方向也没有信息优势**。区间宽度已按历史走查误差的
   经验分位校准（2026-10-02 重算，留出期自 2023-10-02 起）：80% 区间实际覆盖率为
   78.9% / 77.6% / 73.2% / 61.2% / 24.1%（1 日 → 1 年）；同留出期方向命中率
   56.3% / 62.2% / 68.2% / 83.3% / 100%，逐日与「永远看多」一致（+0.0pp），Brier 技能分为负。
   1 年尺度是头号问题：μ 的系统性偏差补不回来，加宽区间也换不来方向上的改进。2026-10-02 的
预注册裁决：17 个候选 × 5 个尺度无一过线，按规则保留线上版本并标注「无统计优势」
（当时是 `quant-v4`；2026-10-02 第二轮修好 ACI 判错区间之后升为 `quant-v5`，
区间数值随之改变，第三轮的 C2 候选同样按预注册判据淘汰；同日引擎加固再升为
`quant-v6` —— 对齐时不再丢弃非交易日观测、ACI 的 α 上界收到 0.5，命中率与覆盖率
因此再次改变；2026-10-03 的 2.0.2 把发布滞后写进因子表（`publication_lag_days`，
利率三因子 1 个工作日）并升为 `quant-v7`，v6 及更早的记录不再可比）；
   页面把覆盖率与永远看多 / 动量两个基准如实并排展示（见 docs/ARCHITECTURE.md 第十一节）。
6. **消息板块不抓全文；中文只译标题与摘要，不译正文**。只使用来源 RSS 提供的标题、
   摘要与链接，不绕过登录与付费墙；正文通过「原文」链接跳转，无法保证目标站点可达。
   中文标题与导语由 LLM 依据这两样生成（见「现状」表的「消息中文化」一行），
   **只压缩原文已有的事实**，因此它读起来会比正文短 —— 那是口径，不是缺陷。
   部分媒体没有公开 RSS，走 Google News 的域名限定检索 —— 经聚合入口的条目带
   `via_aggregator` 明确标注，该入口不可用时按失败计入抓取报告，而不是用其他内容顶替。
7. **全球央行购金口径只有中国**。WGC 月度央行统计页可达但没有免费机器可读接口
   （公开数据 API 路径探测 404），IMF SDMX / DataMapper 实测 502 / TLS 握手失败 / 403 ——
   两边都没有「免费 + 机器可读 + 可稳定复跑」的全球口径，因此 `central_bank` 因子仍是
   中国人民银行官方储备（口径为中国），页面照实标注；不拿单一口径冒充全球。

## 五、明确不做

- 不做实盘交易、不下单、不接券商接口。
- 不做用户资金与账户体系。
- 不提供「保证收益」类表述；所有 AI 产出都必须带免责声明。
- 不为了好看而展示编造的数据 —— 宁可显示「数据不可用」。
