# 消息板块：高权威黄金消息精选

> 状态标记：**现状**（2026-10-02 立项并落地）。本文是该功能这一轮的规约记录；
> 落地后的唯一权威来源是 `README.md` 与 `docs/`（实现口径见 `docs/ARCHITECTURE.md` 第十二节）。

## 一、需求段（做什么、为什么、怎么算做完）

### 背景与问题

页面已经抓取新闻，但新闻只作为 LLM 分析的输入，读者看不到「今天发生了什么」的清单；
现有 RSS 源以综合财经媒体为主，没有权威性分级，也没有重要性 / 置信度口径。
用户要一个能直接读的「消息」板块：高权威来源、按重要性与置信度排序、
分 24 小时 / 7 天 / 30 天三个窗口各取前 10 条，可展开、可点原文、可手动抓取。

### 做什么

1. 新增板块「消息」，三个窗口（24 小时内 / 7 天内 / 30 天内）**各自独立排序、各取前 10 条**；
   三个窗口允许重叠（同一事件可以同时出现在多个窗口，这本身就是需求的一部分）。
2. 每条消息给出：标题、来源、发布时间、**重要性**与**置信度**分数；折叠态即提供「原文」链接；
   展开后给出摘要、评分依据（signals）与同题报道列表（含各自原文链接）。
3. 手动「抓取最新消息」按钮：触发一次全源抓取，显示本次抓取报告（成功源数 / 新增条数 / 失败源）。
4. 后端定时抓取（每小时），页面数据只来自真实抓取结果 —— 抓不到就显示「不可用」与原因。
5. 来源池必须是**高权威且实测可用**的多类来源：央行 / 通讯社 / 行业机构 / 专业财经媒体，
   默认清单在代码里唯一维护，`NEWS_DIGEST_SOURCES` 可覆盖。

### 判据（一条会红的测试或一条能跑证明的命令）

- 单测：评分排序口径（来源权威 > 同内容低权威）、窗口边界（24h / 7d / 30d）、Top10 截断、
  同题聚类与来源覆盖计数、黄金相关性过滤（`gold medal` 这类体育金不得入选）、
  空库返回 `has_data=false` 且给出原因、RSS UTC 时间换算为本地时间。
- 集成：`GET /api/gold/news/digest` 不被 `/news/{news_id}` 抢占；`POST /api/gold/news/digest/refresh`
  落库后 GET 可见；空库不 500（`test_all_endpoints.py` 自动覆盖新 GET）。
- 前端：三 tab、每窗十条、展开可见摘要与同题报道、原文链接 `target=_blank`、
  手动抓取调用「刷新 → 重读」链路并显示报告、失败时只显示不可用原因、无任何内置消息文案。
- 闸门（全绿）：`python -m pytest`、`python -m compileall -q app`、`python scripts/gen_api_doc.py --check`、
  `npm run lint`、`npm test`、`npm run build`、`npm run test:e2e`。
- 变异验证：至少对 4 条新守卫做「改坏 → 必须红 → 复原」并留档（评分权重、窗口边界、
  体育金排除、URL 去重）。

### 明确不做

- 不抓取/缓存文章全文，不绕过登录与付费墙；只用 RSS 提供的标题、摘要与链接。
- 不用 LLM 打分或写摘要（评分必须确定性、可复算；LLM 不参与本板块）。
- 不做中文源（新浪 / FX168 / 金十的公开 RSS 实测已失效，不为凑数放失效源）。
- 不把消息写进现有 `gold_news` 表，也不进入任何 LLM prompt 窗口 —— 避免改变既有分析行为。
- 不做历史归档浏览、全文检索、推送提醒。

### 怎么回滚

- 纯增量：新表、新服务、新路由、新前端区块、新调度任务；不改既有表结构与其他接口行为。
- 回滚 = revert 对应提交（前端区块、路由、调度注册、服务与表各自独立）。
  表可以只留不用；**删除表是破坏性动作，不随回滚自动执行**。

## 二、方案段（架构、数据、接口、排序口径、前端）

### 2.1 来源池（默认清单全部实测可用，2026-10-02）

配置格式 `名称|URL|tier|relevance`，逗号分隔；`tier ∈ {1, 2}`，`relevance ∈ {gold, monetary}`。

| tier | 来源 | 取数方式 | relevance |
|---|---|---|---|
| 1 | 美联储（货币政策） | 官方 RSS（press_monetary） | monetary |
| 1 | 欧洲央行（新闻稿） | 官方 RSS（press） | monetary |
| 1 | 路透社 / 美联社 / 世界黄金协会 | Google News 限定 `site:` + `when:30d` | gold |
| 2 | 彭博社 | 官方 markets RSS | gold |
| 2 | 金融时报 / 华尔街日报 / CNBC / MarketWatch / Kitco | Google News 限定 `site:` + `when:30d` | gold |
| 2 | MINING.COM | 官方 RSS | gold |
| 2 | 英为财情（Investing.com） | 官方大宗商品 RSS | gold |

- Google News 条目从 `entry.source.title` 取真实媒体名展示，按配置 tier 计权威。
- 直连与聚合混用是刻意的：直连源给一手信源，`site:` 限定给无公开 RSS 的通讯社/媒体
  （路透、美联社、FT、WSJ 等的官方 RSS 早已下线 —— 使用失效地址等于编造能力）。

### 2.2 抓取与存储

- 新表 `news_digest_items`（与 `gold_news` 完全隔离）：
  `title / summary / source / source_key / authority_tier / url / published_at / fetched_at / created_at`；
  `url` 唯一（MySQL 前缀索引 191）、`published_at` 普通索引。
- 抓取用 `requests`（超时 10s）取字节再交 `feedparser.parse(bytes)` ——
  `feedparser.parse(url)` 没有超时参数，上游挂起会拖死请求线程。
  线程池并发抓取，单源失败不影响其他源，失败原因进抓取报告。
- 每源最多 40 条；**必须有链接与发布时间**，缺失即跳过并计入报告（不猜测、不回填当前时间）。
- 相关性过滤：`gold` 模式必须命中金融语境的黄金词（`\bgold\b` / bullion / XAU / precious metals，
  且排除 `gold medal` 这类非金融语境）；`monetary` 模式额外接受 FOMC / 利率 / 通胀 / 央行等货币词。
- 标题去掉来源后缀（如 ` - Reuters`）；摘要去 HTML 标签、反转义实体、截 1200 字符。

### 2.3 评分与聚类（确定性，不调用 LLM）

在最近 30 天全集上聚类后统一评分 —— 同一事件在不同窗口分数一致，窗口只是过滤视图：

- `authority`：tier1 = 1.0，tier2 = 0.65
- `relevance`：黄金词权重高于货币词；标题命中按 2 倍计，归一化到 [0, 1]
- `recency`：`exp(-age_hours / 168)`（7 天尺度衰减）
- `coverage`：`min(1, (同题来源数 - 1) / 2)`（2 家 = 0.5，3 家及以上 = 1.0）

```
重要性 = 100 × (0.40·authority + 0.25·relevance + 0.20·coverage + 0.15·recency)
置信度 = 100 × (0.45·authority + 0.30·coverage + 0.25·relevance)
```

- 同题聚类：标题归一化分词（去停用词），Jaccard ≥ 0.6 且共享 ≥ 2 个词 → 并查集合并；
  代表条取簇内重要性最高者；覆盖数按**不同 source_key** 计。
- signals（评分依据）写成人话展示在展开区，例如「一级信源：官方 / 通讯社 / 行业机构」
  「3 家来源同题报道」「24 小时内发布」。

### 2.4 接口

| 接口 | 说明 |
|---|---|
| `GET /api/gold/news/digest` | `{generated_at, has_data, unavailable_reason, last_fetch, windows[]}`；窗口含 `total_clusters` 与 `items[]`（含 rank、分数、signals、related） |
| `POST /api/gold/news/digest/refresh` | 抓取并落库，返回 `{success, fetched_at, total_sources, ok_sources, new_items, sources[]}`；路径以 `/refresh` 结尾 → 自动落严限流档（重操作，不调用 LLM） |

- 路由必须声明在 `/news/{news_id}` **之前**，否则被路径参数吞掉（有守卫测试）。
- 空库：`has_data=false` + 明确原因；前端显示「不可用」而不是任何内置内容。
- 抓取报告写入 cache_manager（key `news_digest_fetch_status`），GET 时读出展示。

### 2.5 前端

- `Messages` 区块（`#messages`，导航「消息」置于「机构」之后）：Radix Tabs 三个窗口，
  列表每条：序号 + 标题 + 来源/时间/重要性/置信度 + 「原文 ↗」；`<details>` 展开摘要、
  评分依据、同题报道链接。
- 顶部元信息：数据时间（上次抓取）与本次抓取报告摘要；按钮「抓取最新消息」，
  进行中「抓取中…」禁用态。
- 空窗口与空库分开：空窗口一句说明；空库按 StateBlock 如实说明原因与重试路径。
- 样式只用设计令牌；文案遵守禁用词表（不得把「实时抓取」等作为能力宣称）。

### 2.6 定时与配置

- 调度任务 `update_news_digest`：`UPDATE_NEWS_DIGEST_CRON`（默认 `25 * * * *`），
  与既有任务错峰；`SCHEDULER_ENABLED=false` 时不注册。
- 新配置项同步进 `backend/.env.example`（模板完整性有守卫测试）。

### 2.7 测试与守卫

- unit：源解析 / 相关性过滤 / 评分 / 聚类 / 窗口与 Top10 / 抓取（假 HTTP，不出网）/ 时间换算。
- integration：两个新路由 + 路由顺序 + 空库 + 抓取落库后 GET 可见。
- 前端 vitest：三 tab、十条、展开、链接、刷新调用链、不可用态无编造内容。
- e2e：导航含「消息」、种子消息可见、展开可见摘要与同题报道。
- 闸门与变异验证见需求段判据。
