## 一、需求段

### 改什么

1. **LLM 供应商不写死**：任何 OpenAI 兼容端点（OpenAI / DeepSeek / 通义 / Kimi /
   Ollama / 小米 MiMo……）只靠 `.env` 三项切换；三项缺任意一项即「未配置」，
   各区块如实显示「暂不可用」，不退回任何内置内容。
2. **联网搜索变显式开关**（默认关）：开才发请求，关时直接走数据库 / RSS 回退。
3. **输出预算可配**（`LLM_MAX_TOKENS`，默认 8192），修掉「投资策略长期显示暂不可用」。
4. **README 的 1:1 复现缺口**：Node 版本下限、Chrome 前置、并不存在的 `.\start_all.ps1`、
   冷启动预期；并把分析区截图重截（此前多张是空态）。

### 为什么

- 写死一家供应商，等于把「能不能跑起来」绑在别人拿不到的 key 上 ——
  别人照着 README 在另一台电脑上配置不出来，复现就不成立。
- 三处**实测**根因（2026-10-01，本机）：
  1. `max_tokens=4096` 把大 JSON 截断：三档策略一次输出可达 4,657 tokens，
     8192 实测可完整返回；
  2. 端点内容风控：看跌类 prompt 会被判 `finish_reason=content_filter`（正文固定为
     "The request was rejected because it was considered high risk"），
     15 条新闻连续两次被拒、10 条通过、12 条被拒；
  3. 联网搜索未开通：5 个参数变体二分全部返回
     `HTTP 400 · web search tool found in the request body, but webSearchEnabled is false`
     —— 这是账号侧开关，不是参数写法问题。

### 怎么算做完（判据）

- **会红的测试**：`tests/unit/test_llm_provider.py`（配置判定 / 默认值 / 旧字段守卫 /
  content_filter 重试）、`tests/integration/test_health.py`（provider 与 model 取自配置）、
  `tests/e2e/test_full_flow.py`（把 `max_tokens` 写死成 4096 即红）、
  `tests/unit/test_news_prompt_format.py`（默认条数只有一个真源）。
  四条守卫都做过变异验证：改坏确认变红。
- **能跑证明的命令**：`README.md`「常用命令」全档；`python scripts/smoke_llm.py`
  在 `LLM_SEARCH_ENABLED=false` 时退出码 0。
- **全局复查**：`rg -i mimo` 只剩三类允许的提及 —— 供应商示例表、
  「MiMo 插件式 web_search」技术说明、致谢。
- **明确不做**：不做前端 key 配置界面（密钥只进 `.env`，见 `docs/10-密钥与隐私.md`）；
  不 bump 版本、不打 tag；不保证联网搜索可用 —— 端点未开通就如实空态，不编造目标价。
- **怎么回滚**：按 commit revert；回滚到旧代码后，把 `backend/.env` 的 `LLM_*`
  改回 `MIMO_*` 即可恢复旧行为。

## 二、方案段

**配置面就是公共接口**（`backend/app/config.py`）：
`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` / `LLM_PROVIDER`（仅展示标签）/
`LLM_MAX_TOKENS` / `LLM_TRUST_ENV` / `LLM_SEARCH_ENABLED` / `LLM_SEARCH_MODEL` /
`LLM_SEARCH_API_KEY` / `LLM_SEARCH_BASE_URL` / `LLM_SEARCH_MAX_KEYWORD`；
`is_configured()` 以「密钥 / 端点 / 模型三项齐备」为准。`/health` 的 `ai_config`
形状保持不变，未配置时如实报 `unconfigured`。

**调用面只走一个入口**（`backend/app/services/llm_provider.py`）：
`get_chat_llm()` 的 `max_tokens` 默认取 `settings.LLM_MAX_TOKENS`；
新增 `retry_on_content_filter()`（被风控重试一次）与 `describe_completion()`
（把 `finish_reason` 与 token 用量压成一行，解析失败时记日志）。
`web_search_service` 全部改走 provider；`is_search_enabled()` 为假时直接返回不可用，
不发起无效请求。

**数据面**：`NEWS_PROMPT_LIMIT = 10` 作为所有分析服务拼 prompt 的统一条数上限
（原 15 条实测触发内容风控）。

**文档面**：中英同步；`CHANGELOG` 的 `[Unreleased]` 记破坏性改名（`MIMO_*` → `LLM_*`，
不留回退）；README 补 Node / Chrome 前置、删不存在的 `start_all.ps1`、写清冷启动预期。

**取舍**：端点侧的两件事（内容风控、搜索插件是否开通）代码无法自行决定，
只能重试 + 如实降级；宁可页面显示「暂不可用」，也不摆内置内容。
