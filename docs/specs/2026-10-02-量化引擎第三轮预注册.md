# 第三轮预注册：把「取样单位」与「回看窗」分开

- 上游：`docs/specs/2026-10-02-量化策略提升路线图.md`（§6.1 候选清单封板处）、
  `docs/specs/2026-10-02-量化引擎第二轮预注册.md`（§六.5 判据、§六.6 动机）
- 状态：目标（候选 C2 的定义与判据在跑数之前写死；裁决结果回来后补在「三、裁决」）

---

## 一、需求段

### 改什么

第二轮把「每注校准」作为候选 C1 试过一次：`stride = horizon`（每 `horizon` 行才把一次
实现误差计入校准样本）在 60 日同时把覆盖率拉向名义（0.744 → 0.772）并把宽度收窄
（0.891 倍），但覆盖率差 0.8pp 没跨过事先写死的 0.78，按规则淘汰。

淘汰时记下的那条线索是：**C1 一次改了两个自变量** —— 它既把取样单位从「行」换成了「注」，
又顺手把回看窗整个去掉（`window=None`）。因此分不清 60 日剩下那 5.8pp 的缺口该记在
「取样单位」还是「回看窗」头上。本轮把这两个旋钮分开，只测其中一个：

**候选 C2 = C1 + 回看窗**（`stride = horizon`、`γ = 0.05`、半衰期 60 注，与 C1 逐值相同，
只把 `window` 按日历等值加回来）。

### 为什么

- 第二轮实测（26 年面板，开发期 `mature < HOLDOUT_START`）：
  - 线上口径（`row` 取样、750 行回看窗、250 行半衰期）在 60 日的**平静档**覆盖率只有
    **0.5625**，热闹档 0.7353 —— 缺口几乎全在平静档；
  - C1（`bet` 取样、不设窗）两档是 0.781 / 0.765，差 +1.6pp，把平静档拉回来了。
- 也就是说「每注取样本」这个方向本身是对的；剩下要回答的是**回看窗该不该留、留多长**。
  现有 C1 的半衰期是 60 注，对 60 日尺度等于 3600 个交易日 —— 比整个面板还长，
  等于「不衰减」，这不像一个有意选定的学习速率，更像把窗去掉之后的副作用。

### 怎么算做完（判据）

**这三条在跑数之前写死，任一不满足即淘汰，不得回头改阈值。**

1. **目标尺度**：开发期 60 日覆盖率 ∈ **[0.78, 0.82]**（与 C1 同一条判据，不回退）；
2. **不许靠撑宽换覆盖**：开发期 60 日区间宽度 ≤ 线上口径（B0 / C0）的 **1.05 倍**；
3. **不许只在某一档达标**：开发期 60 日「平静档 − 热闹档」覆盖率差 ≤ **5pp**
   （阈值沿用 §六.3 的写法；分档口径与 `backtest.coverage_by_vol_regime` 完全一致，
   expanding 阈值 + 每档 `stride = h` 抽独立下注，下注不足 30 次只报次数）。

裁决用开发期，不看留出期（留出期已被第一/二轮看过，不再算样本外）；命令固定为
`python scripts/quant_lab.py --horizons 5,20,60 --group baseline --group calibration`，
对照候选是 C0（与线上逐值相同的控制）与 C1（上一轮被淘汰的那个）。

**通过则**：把 `bet_window` 切成交付默认（`definitions.MODEL_VERSION → quant-v6`），
研究台的基线族描述同步改写；
**不通过则**：线上口径一字不动，只把 `MODEL_VERSION` 补记到 `quant-v5`
（第二轮 §六.5 的欠账：ACS 判错区间那次修复改了线上区间的数值，版本号却没跟上）。

### 明确不做什么

- 不重新调 γ / 半衰期 —— 第二轮已经用 64 档网格证明这条路在 20 / 60 日抬不进 0.78–0.82，
  再调一次等于对同一份数据重复开火；
- 不动因子集、权重、回归窗口、区间口径：C2 只碰「校准样本怎么数」这一件事；
- 不因为 C2 过了就顺手换目标定义（下行择时 / 幅度技能）—— 那是独立的一轮。

### 怎么回滚

`calibration_settings()` 是唯一的口径真源，候选与线上默认都由它出口。回滚 = 把
`DEFAULT_CALIBRATION_MODE` 改回 `CALIBRATION_ROW` 并同步 `MODEL_VERSION`；
候选本身可以留在清单里（它是研究台的一档，不影响交付口径）。

### 判据的载体（会红的测试）

- `tests/unit/quant/test_calibration_modes.py`：`bet_window` 的四个常数与窗口折算逐值钉住，
  把 `window` 换成 `None`（退化成 C1）或把 γ / 半衰期换成 `row` 档的值都必须红；
- `tests/unit/quant/test_quant_lab.py`：候选表与 §6.1 逐项对齐，C2 只写在代码里没写进
  spec（或反过来）都必须红。

## 二、方案段

### 1. 口径定义（`app/services/quant/engine.py`）

新增第三种取样单位 `CALIBRATION_BET_WINDOW = "bet_window"`，加进 `CALIBRATION_MODES`。
`calibration_settings(mode, horizon)` 的第三个分支：

```
γ          = ACI_GAMMA_BET = 0.05            （与 C1 同值：学习速率不是本轮的变量）
half_life  = ACI_HALF_LIFE_BET = 60          （单位：注，与 C1 同值）
window     = max(MIN_ERRORS_FOR_SIGMA, CALIBRATION_WINDOW // horizon)   （单位：注）
stride     = horizon
```

`window` 的折算规则是**日历等值**：线上口径的回看窗是 `CALIBRATION_WINDOW = 750` 个交易日，
换成「每 `horizon` 行才记一注」就是 `750 / horizon` 注 —— 同样的日历跨度，只是数的单位变了。

**下界为什么是 `MIN_ERRORS_FOR_SIGMA`**：250 日尺度上 `750 // 250 = 3`，那会让经验分布
从 3 个样本里取分位。`calibrate_distribution` 的 `min_samples` 守卫本来就是「样本不够就
返回 NaN、由调用方退回正态」，窗比它更短等于让守卫在算完之后才失效 —— 宁可不缩，
也不产出一个说不清置信度的数（见 `docs/00-产品方向.md` 的「不许编造数据」红线）。

折算规则在四个分辨率上的**实际取值**（跑数之前先列出来，免得事后才发现下界一直是承重的）：

| 尺度 h | `750 // h` | 生效的窗（注） | 半衰期（注） | 窗是否承重 |
|---|---|---|---|---|
| 1 日 | 750 | 750 | 60 | 否（等同不设窗） |
| 5 日 | 150 | 150 | 60 | 否（2.5 个半衰期，尾部权重已很轻） |
| 20 日 | 37 | **60（下界）** | 60 | 是 |
| 60 日（目标尺度） | 12 | **60（下界）** | 60 | 是 |
| 250 日 | 3 | **60（下界）** | 60 | 是 |

也就是说：h ≤ 12 时 C2 测的是「日历等值的窗」，h ≥ 13 时下界承重，C2 实际测的是
「分布只保留最近一个半衰期内的注」。两种读法都要在裁决里如实写明 —— 淘汰的话，
下一轮得知道被否掉的是哪一种。

### 2. 研究台（`scripts/quant_lab.py`）

`candidates()` 增一档 `C2`（组 `calibration`），描述里写明「每注计一次 + 回看窗 = 750/h 注
（日历等值，下限 60 注）」；`GROUP_LABELS["calibration"]` 从「校准样本两档」改成
「校准样本三档」。这一档**不是**新的线上默认 —— 研究台只负责把候选算出来。

### 3. 文档

- `docs/specs/2026-10-02-量化策略提升路线图.md` §6.1 的「校准样本」一行：数量 2 → 3，
  候选串里加上 C2，并说明它来自第二轮 §六.6；
- 本文档「三、裁决」在跑完之后补实测表与结论（含被淘汰时同样要记的线索）。

### 4. 判据的实现（`tests/unit/quant/test_calibration_modes.py`）

把三种取样单位的 `calibration_settings` 输出逐值断言：`row` / `bet` / `bet_window` 的
γ、半衰期、窗、stride；并断言 `bet_window` 的窗随 `horizon` 变化（5 / 20 / 60 / 250
四个尺度各算一次）与下界生效。
