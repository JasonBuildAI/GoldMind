# 消息中文化与板块升级、金价刷新时间处处可见

> 状态标记：**目标**（2026-10-03 立项）。本文是这一轮的规约记录（需求段 → 方案段）；
> 落地后唯一权威来源回到 `README.md` 与 `docs/`（实现口径进 `docs/ARCHITECTURE.md` 第十二节，
> 产品现状进 `docs/00-产品方向.md`）。

## 一、需求段（做什么、为什么、怎么算做完）

### 背景与问题

1. **消息全是英文。** 消息板块的 13 个高权威来源（美联储 / 欧洲央行 / 路透 / 美联社 /
   世界黄金协会 / CNBC / Kitco ……）都是英文 RSS，标题与摘要原样呈现，
   中文读者得自己翻译。`docs/00-产品方向.md` 第四节第 6 条把这写成已知限制
   （「不抓全文、不做翻译」），用户现在明确要求补上「中文翻译 + 大致介绍」。
2. **消息没有独立入口。** 消息是「驱动」节里三块中的一块，侧边栏导航里根本没有「消息」这一项；
   想读消息得先知道它在「驱动」下面。用户要求把它升成一等板块。
3. **有些金价没写是什么时候的。** 金价至少出现在五处：侧边栏今日速览、行情节、
   今日结论「当前价格」、投资策略降级快照、量化预测「基准价」与公允价值「市场价」。
   其中**今日结论、投资策略快照、量化基准价**只给数字不给时间 —— 读者无法判断
   「$4,170.09 是刚才的，还是昨天的收盘」。用户要求所有展示国际金价的地方都写清
   最后一次刷新时间。

### 做什么

#### A. 消息中文化（中文标题 + 中文导语）

1. 每条消息增加两个中文字段：`title_zh`（中文标题）与 `brief_zh`（2–3 句中文导语）。
2. 由 LLM 生成，**抓取后自动批量执行**：一次最多处理 `NEWS_TRANSLATE_BATCH`（默认 30）条，
   按 `published_at` 倒序取**尚未翻译**的条目（最新优先 = 页面上看得见的优先），
   一批一次 LLM 调用。已翻译的条目永不重复调用。
3. 口径硬约束（红线 1 在翻译链路上的落地）：`brief_zh` 只能**压缩来源摘要里已有的事实**；
   不得添加原文没有的数字、机构名、目标价、日期、背景或因果解释；原文没写的一律不写。
   prompt 里逐条声明，`title_zh` 只做翻译，不做改写。
4. 降级必须诚实且**逐条可解释**：LLM 未配置 / 当日预算用尽 / 调用失败 / 该条没有摘要 ——
   各给具体原因；页面显示英文原标题并标「中文翻译暂不可用」+ 原因。
   **绝不**用词典或模板凑一段中文，也绝不把没翻译的条目标成已翻译。
5. 中文是**叠加**不是替换：英文原标题与来源摘要原文始终保留，AI 产出带标注，
   读者可以逐条对照核对。
6. 首次上线时库里已有的历史条目由同一条批量链路逐步补齐（每小时一次，最新优先），
   启动引导再补一批；不写一次性回填脚本。

#### B. 消息升为一级板块

7. 侧边栏导航在「驱动」之后、「量化预测」之前增加「消息」，指向页内 `#messages` 节。
8. 消息从「驱动」节搬出来，成为独立节「消息」；「驱动」只留看涨因素、看跌因素与机构观点。
9. 与结构有关的守卫、字段覆盖测试、浏览器 e2e **同一次改到位**（不是后续补 commit）。

#### C. 金价刷新时间处处可见

10. 每一处展示**当前国际金价**（不是机构目标价、不是模型预测价）的位置，
    都必须同时给出该价格的时间、口径与来源；时间取**这个价格自己的** as-of 字段，
    不得用浏览器时钟或页面加载时间顶替（红线 5）。
11. 覆盖清单（现状 → 本轮）：

    | 位置 | 现状 | 本轮 |
    |---|---|---|
    | 侧边栏「今日速览」大数字 | 有口径 + 时间 + 来源 | 改用统一组件，措辞统一 |
    | 行情节结论行「纽约黄金 $x」 | 无时间 | 补 as-of |
    | 行情「最新价格」QuoteBlock | 有数据时间 | 改用统一组件，措辞统一 |
    | 行情快照表「口径时间」 | 有 | 不动 |
    | 逐日金价 / 对照表「数据截至」 | 有 | 不动 |
    | 今日结论「当前价格」 | **无时间、无口径** | 后端补 `price_as_of` / `price_basis_label` / `price_source`，前端展示 |
    | 投资策略降级快照「最新价」 | **无时间、无口径** | 快照补 `as_of` / `basis` / `basis_label` / `source` |
    | 量化预测「基准价」 | **无时间** | 用接口已有的 `as_of` + `price_basis` 展示 |
    | 公允价值「市场价」 | **无时间** | 同上（同一份 `as_of`） |

12. 「金价刷新时间」这句话只在**一个组件**里拼（`GoldPriceAsOf.vue`），
    五处引用同一个组件 —— 同一事实只有一个来源，措辞不会各漂各的。
13. 价格缺失 / as-of 缺失时如实写「金价刷新时间未知（后端未返回）」，不倒推、不填当前时间。

### 明确不做

- **不做全文抓取与全文翻译**：仍然只用来源 RSS 的标题、摘要与链接，不绕付费墙；
  中文导语的长度上限跟着摘要长度走，不因为「介绍」二字去猜正文。
- **不做中文来源**：不为凑数接失效的中文 RSS（新浪 / FX168 / 金十实测已失效）。
- **不用翻译改写评分**：重要性 / 置信度 / 排序仍只由英文原文的确定性评分决定，
  中文不参与打分，也不参与聚类。
- **不把中文并入分析 prompt**：多空因子 / 机构观点 / 投资建议 / 市场总结的输入仍是
  原始英文标题与摘要 —— 换语言会改变模型行为，那是另一件事，这一轮不碰。
- **不做手动「翻译这一条」按钮**：自动批量 + 启动补一批已经覆盖可见条目（YAGNI）。
- **不改机构目标价与预测价的标注**：那是预测不是当前金价，本轮不动。

### 怎么回滚

- 纯增量 + 加列：新服务、新配置项、新组件、新节；四个新列可空，
  回滚代码后旧代码看不见它们（不删列、不删数据）。
- 回滚 = revert 对应 commit；`news_digest_items` 的中文列可以只留不用。
  删除列是破坏性动作，不随回滚自动执行。

## 二、方案段（架构、数据、接口、口径、前端）

### 2.1 数据模型与迁移

`news_digest_items` 增加四列（全部可空，旧行不受影响）：

| 列 | 类型 | 含义 |
|---|---|---|
| `title_zh` | VARCHAR(500) | 中文标题；NULL = 尚未翻译 |
| `brief_zh` | TEXT | 中文导语（2–3 句，压缩自来源摘要） |
| `translated_at` | TIMESTAMP | 这条译文是何时产出的 |
| `translation_model` | VARCHAR(100) | 产出译文的模型名 —— 换模型后旧译文可被识别为陈旧并重翻 |

- 迁移 `scripts/migrate_news_digest_translation.py`，入口 `apply(engine)`，
  用 `inspect` 判断缺哪列、`ALTER TABLE ... ADD COLUMN` 逐列补齐，幂等；
  与 `migrate_news_digest_url.py` 同构（CLI `--apply/--dry-run/--rollback` + 引导调用 `apply`）。
- 注册进 `bootstrap.MIGRATIONS`：key `news-digest-translation-columns`，`alters_existing=True`
  （SQLite 下迁移前自动备份）。
- `backend/schema.sql` 同步加四列（`test_schema_matches_models.py` 守住模型 ↔ DDL 一致）。

### 2.2 翻译服务（`backend/app/services/` 下的 news_translation.py）

一个职责：**把待翻译的消息批量变成中文，或者如实说为什么没做到**。

```
class NewsTranslationService(db):
    pending(limit)      -> 按 published_at 倒序取 title_zh 为空（或 translation_model 非当前模型）的条目
    translate_pending(limit) -> 一次 LLM 调用 → 校验 → 落库 → 返回报告
```

- **一次调用一批**：prompt 里带 `id` + 标题 + 截断到 600 字符的摘要；
  要求只输出 `{"items":[{"id":int,"title_zh":str,"brief_zh":str}]}`。
- **校验（确定性，不信任模型）**：`id` 必须落在本批输入集合内（越界丢弃）、
  两个字段都必须是非空字符串（空则丢弃该条）、`brief_zh` 截断到上限。
  校验不过的条目**不写库**，在报告里计 `failed`。解析失败整批不写。
- **调用走唯一入口**：`llm_provider.get_chat_llm(temperature=0.2)` +
  `llm_provider.invoke_with_retries`（每日预算在这里扣，超限抛 `LLMBudgetExceeded`）。
  不经任何旁路构造客户端（红线 3）。
- **返回报告**：`{requested, translated, failed, skipped, reason, model, at}`。
  `reason` 是给页面看的一句话；成功时为 `None`。
- **写库**：只 UPDATE 目标行，`translated_at = timeutil.now_naive()`，
  `translation_model = 当前模型名`；不删行、不动英文原文。

### 2.3 触发时机

1. **抓取后**（`NewsDigestService.fetch_all_sources` 落库之后）：调一次
   `translate_pending(NEWS_TRANSLATE_BATCH)`；结果写进抓取报告
   （`translated` / `translation_reason`），失败不影响抓取本身成功与否。
2. **启动引导**（`bootstrap._phase_news` 末尾）：无论这一步有没有真抓取，都补一批；
   全部已翻译时零调用（幂等）。
3. 两条路径共用同一个服务与同一份配置，不写第二套口径。

### 2.4 配置

| 配置项 | 默认 | 含义 |
|---|---|---|
| `NEWS_TRANSLATE_ENABLED` | `true` | 关掉即完全不调用 LLM 翻译（页面全部显示英文 + 原因） |
| `NEWS_TRANSLATE_BATCH` | `30` | 一次批量翻译的条目上限（= 三个窗口可见条目的上限） |

两项同步进 `backend/.env.example`（模板完整性有守卫测试）。

### 2.5 接口

`GET /api/gold/news/digest` 的每条 item 增加：

```jsonc
{
  "title_zh": "…" | null,
  "brief_zh": "…" | null,
  "translated": true | false,
  "translation_model": "…" | null,
  "translated_at": "2026-10-03T12:40:00" | null
}
```

响应体顶层增加一块翻译状态（供页面统一解释「为什么这条没有中文」）：

```jsonc
"translation": {
  "enabled": true,
  "model": "mimo-v2.6-flash",
  "pending": 12,             // 最近 30 天里还没翻译的条数
  "reason": null             // 有 pending 时的原因（未配置 / 预算用尽 / 上次失败）
}
```

`POST /api/gold/news/digest/refresh` 的报告增加 `translated` 与 `translation_reason`。

`GET /api/analysis/summary` 增加 `price_as_of` / `price_basis_label` / `price_source`
（与 `current_price` 同一时刻、同一来源写入，取不到金价时三者均为 `null`）。

`GET /api/analysis/investment-advice` 的 `price_snapshot` 增加
`as_of` / `basis` / `basis_label` / `source`（口径是 `close`，来源是 `gold_prices` 表）。

> 口径名与中文标签只从 `services/price_basis.py` 取；量化接口的 `as_of` 与 `price_basis`
> 已经有了，本轮只是让前端用上。
