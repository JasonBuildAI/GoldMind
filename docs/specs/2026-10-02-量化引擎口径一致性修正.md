## 一、需求段

### 改什么

`engine.py` 的模块文档承诺「方向、概率、目标价、区间、情景只从这一个分布出发」（`engine.py:22-23`），
`scenarios.py` 也写着「口径（与方法论一致，不另算一套数字）」（`scenarios.py:3`）。
2026-10-02 逐行核对代码后确认：**这句话现在有四处不成立**，而且其中一处会让概率被系统性压向 50%。

1. **概率与区间不是同一个分布。** 区间边界用「非对称经验分位 + ACI」（`engine.py:396-402`），
   而 `p_up` 用 `Φ(μ/σ)`（`engine.py:415`）——一个对称正态尾概率。
2. **`p_up` 用的 σ 是为「区间宽度」放大过的那个 σ。** `engine.py:373-377` 先把误差标准差乘上
   经验分位因子 `q80(|e| / (z80·σ))`（本意是让 80% 区间真的盖住八成误差），紧接着 `engine.py:415`
   就拿这个放大后的 σ 去算 `Φ(μ/σ)`。校准因子 `> 1` ⇒ `μ/σ` 变小 ⇒ **概率恒定向 0.5 收缩**。
   这与实测吻合：全样本 Brier 技能分在五个尺度上全部为负（1/5/20/60/250 日 =
   −0.003 / −0.008 / −0.022 / −0.072 / −0.235，`backend/cache/quant_research.json`），
   即概率输出劣于「一律回答基准率」的常数预测——概率不是没信息，是被错误的尺度稀释了。
3. **情景用的是第三个口径。** `scenarios.py:6-9` 声明「未来 h 日收益 ~ N(μ, σ²)」并取 q25/q75 生成
   Base/Bull/Bear，而 μ/σ 直接取快照里那个**已被经验分位放大**的 σ。于是四分位边界比主分布更宽，
   且与 80% 区间不构成嵌套关系（Bear 边界可能反而比 80% 区间下界更靠外）。
4. **四层分解有数值溢出。** `decompose.py:191` 的 `np.expm1(beta·(current − mean))` 无界，
   测试跑动时已经真的报出 `RuntimeWarning: overflow encountered in expm1`
   （`tests/unit/quant/test_decompose.py::test_latest_ignores_everything_after_as_of` 一次运行可见）。
   溢出后溢价变成 ±inf，页面与接口拿到的数不可解释。

另外两条属于「评估口径」而非「模型口径」，一并写清楚：

5. **陈旧因子只被标注、没被停用。** `max_age_days`（`definitions.py:100-101`）只在
   `factor_states` 里算成 `STATUS_STALE`（`engine.py:536-540`），全项目再无第二处引用；
   `align_factors` 是**无界前向填充**（`engine.py:123`），`composite_score` 只按「非 NaN」计入
   （`engine.py:190-193`）。结果：月频的央行储备超过 62 天不更新时，界面写「陈旧」，
   得分照旧按该因子的最高档权重（60/250 日 1.0）贡献 —— 显示层与计算层说的是两件事。
6. **长尺度的评估结果没有带上它自己的有效样本量。** 重叠样本折算 `n_eff = n/h`（`stats.py:256-260`）
   已经算进 metrics，但研究接口/页面把 24.1%、49.1% 这类覆盖率当结论展示，不并列 `n_eff`。
   实测：250 日留出期 506 个样本 = **2.0 个有效观测**，覆盖率 95% CI 是 [4%, 45%]；
   250 日全样本 `n_eff = 17.6`，命中率 CI 是 [50.8%, 82.3%]（同一份缓存）。
   在这些数字上不写 `n_eff`，等于把一个不可判定的量当成可改进的缺陷读数。

### 为什么

第 1–3 条是同一件事的三个面：v3 已经把「方向 / 概率 / 区间」统一到走查校准分布上
（`docs/specs/2026-10-01-预测口径统一.md`），v4 只把**区间宽度**换成了经验分位，没有回头改
概率与情景的分位来源，于是「同一个分布」退化成「区间用经验分位、概率用正态、情景用正态 × 放大 σ」。
这既违反自己的设计约束，也是 Brier 技能分全线为负的直接机制之一。

第 4 条是会让输出变成不可解释数字的真实缺陷（已在测试运行里复现）。

第 5 条违反本项目的红线精神：新鲜度是「能不能用」的判断，不该只影响颜色。

第 6 条不是模型问题，是**别把噪声当成待修复的缺陷** —— 路线图 §三.2 把「250 日覆盖率 24.1% 未达标」
记成未解决问题，但该结论本身建立在 2 个有效观测上，任何校准方案都无法在这个尺度被验证。

### 怎么算做完（判据）

判据分两类：**一致性/健壮性**（可由构造证明，不需要新数据）与**准确率**（必须走预注册，见下）。

- **会红的测试**（每条都要变异验证：改坏必须红）：
  - `tests/unit/quant/test_engine.py` —— 新增：`p_up` 必须等于「校准分布里 `−μ/scale` 之上的经验尾部比例」，
    且与区间边界自洽（`p_up` 与 80% 区间用同一批分位样本）。把 `probability_up` 改回
    `Φ(μ/σ_inflated)` 必须红；把 ACI 分位与概率用误差序列改成不同来源必须红。
  - `tests/unit/quant/test_engine.py` —— 新增：在构造的「重尾且右偏」误差序列上，
    旧的 `Φ(μ/σ_enlarged)` 与新的经验尾部概率之差 ≥ 一个下限（钉住「概率被压向 0.5」这个具体病症）。
  - `tests/unit/quant/test_scenarios.py` —— 新增：Bull 下界 ≥ 80% 区间上界、Bear 上界 ≤ 80% 区间下界
    （四分位必须嵌套在 80% 区间内），且三情景概率之和 = 1。把情景改回 `N(μ, σ_enlarged)` 必须红。
  - `tests/unit/quant/test_decompose.py` —— 新增：把 `vix` 尾部改成极端值，断言
    `decompose_latest` 输出的四块全部有限（无 inf/nan）且恒等式「中枢+需求+风险+残差 = 市场价」仍成立。
    去掉溢出保护必须红（并确认 pytest 不再出现 `RuntimeWarning: overflow`）。
  - `tests/unit/quant/test_engine.py` —— 新增：`align_factors`/`build_signals` 的填充上限：
    低频序列超过该因子的新鲜度上限后不得进入合成得分；同时回测的可用因子计数走同一判据
    （否则回测与实盘不是同一个模型）。把上限改成无界必须红。
  - `tests/unit/quant/test_no_lookahead.py` 保持全绿：上面所有改动都不许引入前视
    （垃圾值守卫不许被新代码绕过）。
- **能跑证明的命令**：`cd backend && python -m pytest` 全绿；`python -m compileall -q app`；
  `python scripts/gen_api_doc.py --check`；`cd app && npm run lint && npm run build`。
  覆盖率/概率口径变化会同时动 `docs/API.md`（由生成器产出），必须同批提交。
- **准确率结论怎么算**：本轮的改动会改变 `p_up` 与情景数字，但**不构成「预测能力提升」的证据**。
  `HOLDOUT_START = 2023-10-02`（`definitions.py:52`）这个留出窗口已经被 2026-10-02 的 17 候选实验
  看过并汇报过（`docs/specs/2026-10-02-研究台报告.md`），再用它做入选裁决就不叫样本外。
  因此本轮只允许声明「口径一致、输出可解释、概率不再被错误尺度稀释」；
  任何「更准」的说法必须等新的前向留出期积累够、并重新预注册。

### 明确不做什么

- 不改因子集合、不改任何权重、不改 `MODEL_VERSION` 之外的口径定义（因子集与权重正被另一处改动）。
- 不引入深度学习、不实盘、不学权重（沿用既有理由）。
- 不在本轮给「命中率提升」下任何结论。
- 不动 `HOLDOUT_START` 的语义（它是历史事实）；新增「下一个未接触窗口」另立名字。

### 怎么回滚

`git revert` 本轮各 commit；概率/情景口径都是纯函数层，回退代码即回到 v4 现状，
历史评估按 `model_version` 分列保存，不受影响。

## 二、方案段

### 1. 一个分布，四个出口（`engine.py`）

把「走查校准分布」作为唯一的概率源：

```
z_t   = (r_t − μ_t) / scale_t          studentized 误差，已按实现时间右移（现有 errors/scale）
F̂_n   = 半衰期加权经验分布（最近 CALIBRATION_WINDOW 个已实现 z，ACI 已用同一批样本）
区间   = μ + scale × [ F̂_n⁻¹(α/2), F̂_n⁻¹(1−α/2) )   ← 现有 ACI 递推选 α，保持不变
p_up  = 1 − F̂_n( −μ / scale )                         ← 换掉 Φ(μ/σ_inflated)
情景   = μ + scale × F̂_n⁻¹(q),  q ∈ {0.25, 0.75}       ← 换掉 N(μ, σ_inflated) 的四分位
```

- 由此 `p_up` 与区间按构造自洽：`α = 0.2` 时区间两端对应的累积概率恰为 0.1 / 0.9，
  四分位必然嵌套在 80% 区间内 —— 这是可以写成测试的恒等式，不是一个参数。
- `uncertainty` 字段保留（页面与接口在用它显示「幅度」），但**不再**作为 `p_up` 的分母；
  新增 `probability_source` 字段如实标注这个概率来自哪个经验分布，页面 tooltip 同步。
- σ 的 q80 放大只用于「区间宽度」的旧出口，若与 `F̂_n` 重复放大则去掉一处 —— 实现时以
  「覆盖率的唯一来源是 `F̂_n`」为准，不留两套尺度。

### 2. 新鲜度进入计算层（`engine.py` + `backtest.py`）

- `align_factors` 增加按因子的**填充上限**（用 `definitions.max_age_days` 换算成交易日，
  超上限不再前向填充 → 该行该因子为 NaN）。
- 于是「陈旧 = 不参与合成」在实盘快照、回测走查、研究台三条路径上同时成立，
  且回测的可用因子判据（`backtest.py:110`）与 `build_snapshot` 的 `MIN_AVAILABLE_FACTORS` 是同一套。
- 已知影响：月频 `central_bank`（上限 62 天）与周频 `cftc_positioning`（14 天）会有
  「发布间隔内的空窗」，命中率样本数下降 —— 这是如实反映，不是回归。

### 3. 分解层去溢出（`decompose.py`）

对 `beta·(current − mean)` 施加与 `expm1` 等价的有限截断（按对数贡献 ± 上限，
上限取自拟合期 |beta·disp| 的经验分位，不写死魔数），保证三块溢价有界、恒等式仍成立。

### 4. 评估层把不确定性摊开（`backtest.py` + 接口 + 页面）

- 每个覆盖率/命中率输出旁边固定带 `effective_sample_size` 与 `*_ci95`（metrics 里已算好）。
- `service.py` 的 research 负载补 `n_eff` 字段，`app/src/research/` 与 `app/src/sections/Quant.tsx`
  在长尺度卡片显示「≈N 个独立观测」；`scripts/gen_api_doc.py` 同步。
- 覆盖率 `n_eff < 20` 时，页面把该覆盖率标为「样本不足，不作达标判据」，
  与 `docs/specs/2026-10-02-量化策略提升路线图.md` §三.2 的「未达标」表述区分开。

### 5. 留出期纪律（`definitions.py`，需与并发改动协调后再动）

- 保留 `HOLDOUT_START`（历史事实），新增 `ACTIVE_HOLDOUT_START`：本轮实验一律以
  「结论公布日之后的窗口」为留出期，当前尚无观测 ⇒ 所有候选一律 `insufficient`，
  如实返回「前向留出期尚未开始积累」。这是防止「同一窗口被反复预注册」的机械守卫。
