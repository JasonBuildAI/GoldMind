# 2026-10-03 第三轮评审整改（spec）

> 来源：三张评审截图（用户提供，不入库）。状态：**进行中**。
> 目的：项目核心是「更可靠的信源、更好的金价预测」。评审指出当前运行中的
> 产物含大量低价值 / 误导性内容；本 spec 逐条给出处置与判据。
> 原则：能落地就落地；落不了地就**如实降级 + 写明原因**；任何一步都不编造数据。

## 一、需求（做什么、为什么、怎么算做完）

1. 逐条处置评审的 21 条主项 + 2 条次要项 + 3 条事实纠正（见第二节）。
   每条要么「完成」（代码 + 测试或可复跑命令 + 文档），要么
   「未落地（原因）」（页面与文档如实标注不可用，绝不补数）。
2. 判据（做完的证明）：
   - 第二节每行都有终态，不允许停在「待做」；
   - 每条完成项附测试名或可复跑命令；
   - 全档闸门（`README.md`「常用命令」）全绿；
   - 页面不再出现评审点名的低价值产物（占位行、未校准偏向、未到期噪音）。
3. 明确**不做**：
   - 不采购付费数据（CME 结算、彭博等）；无免费/合规依据的源不硬接，标未落地；
   - 不改本机 `.env` 里的密钥（不可逆、须用户账户侧操作）——只出文档与守卫；
   - 不为「尽快可判」伪造裁决阈值；贝叶斯先验参数必须写在明处。
4. 回滚：每单元独立 commit；数据清理/迁移脚本先 `--dry-run`、执行前把被改文件
   整体备份到仓库外、脚本内写明回滚命令；本机密钥不动。
