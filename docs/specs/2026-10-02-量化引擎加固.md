## 一、需求段

### 改什么

2026-10-02 的独立复核（只读打开 26 年面板 `backend/goldmind-long.db` + 变异验证）
在 `quant-v5` 上确认了 9 类问题。本轮把它们一次修到位：**每条都要先有一条会红的
测试**，且每条新守卫都做一次变异验证（改坏必须红）。

| # | 问题 | 证据（复核实测） | 危害 |
|---|---|---|---|
| 1 | `engine.align_series` 用 label 精确 `reindex`，**静默丢弃不在金价日历里的观测** | 2414 条观测不在日历内；受影响行数：bitcoin 3497、credit_appetite 1644、real_yield_10y 752、cftc_positioning 536、central_bank 25 | 引擎输入 ≠ 页面显示（`factor_states` 读原始序列），且周频因子整周滞后 |
| 2 | `ACI_ALPHA_CAP = 0.6 > 0.5` → 区间下界越过情景下界 | h=250：1040 行 α>0.5、1036 行 `interval_low > scenario_low`、1033 行 `scenario_high > interval_high`；h=60 为 81/80 | 破坏 `scenarios.py` 声明的「情景 ⊂ 区间」；名义水平漂到 40%–99.5% |
| 3 | 名义水平与 σ 来源对用户不可见 | `interval_alpha` / `distribution_mode` 从未离开 `engine`；h=250 有 1603 行 α 贴下界 0.005 | 用户看到「80% 区间」，实际名义水平可能是 99.5% |
| 4 | μ 封顶在线上不可见 | `expected_capped` 只进回测指标（`backtest.py:366`），`SignalSnapshot` 无此字段；h=250 触发率 4.48% | 展示的是封顶后的值，却无任何标记 |
| 5 | 研究台仍按**历史留出期**裁决，且丢掉样本量闸门 | `quant_lab.py` 抬头写「裁决只认前向留出期」，但 `PERIODS` 无 `forward`、`decide()` 读 `holdout`、`rule_flags` 不传 `effective_sample_size`；实跑 `--horizons 250 --group baseline` 打印「未过线（保留线上版本）」，当时只有 9 次独立下注 | 把「不可判定」当「不及格」——正是第二轮宣布消灭的错误；两条路（API / 脚本）分叉 |
| 6 | `bet` 校准档在长尺度从未生效，且报告不显示 | h=250 实测 5413/5413 行退回 `normal`（最多 21 注 < 60 注门槛）；`backtest`/`quant_lab` 都不输出 `distribution_mode` | C1/C2 这类候选在长尺度的成绩是假的 |
| 7 | 流水 `recorded_at` 混两个时钟 | 迁移抄 `COALESCE(created_at, updated_at)`，而 `created_at` 是 `server_default=func.now()`（SQLite = UTC）；实测差 8 小时 | 违反红线五；凌晨写入的值会渗进前一天的 `--as-of` 面板 |
| 8 | 流水回填只在「流水表全空」时执行 | `ledger_backfill_rows` 见非空即返回 0；而启动 `create_all` 会先建出空表、任一次同步又会写几行 | 68k 历史观测可能永不入流水，`--as-of` 静默给出残缺面板 |
| 9 | 筛查层阈值没有任何「常量↔文本」守卫 | 实测把 `MIN_T_TO_PASS` 3.0→2.8、`MIN_FORWARD_BETS` 20→5、`MIN_SCREEN_SAMPLES` 300→200，14 条筛查测试**全绿** | 与第一轮预注册常量（有守卫）标准不对等 |

同时修掉三处**数据/口径小错**与一批**文档分叉**：

- `cftc_net_oi_ratio` 是比值（0.40）却标成 `%` → 显示「0.40 %」；
- `sources/gpr.py` 没有发布滞后平移（其它四个后发布源都有）→ 第二轮的
  「gpr_daily 20 日 t=−2.64」这条实测依据带前视；
- `sync._missing_reason` 的 `factor_key` 参数没被使用、且忽略 `skipped` 源 → 原因张冠李戴；
- `docs/ARCHITECTURE.md` 的覆盖率仍是修复前的 `78.9/77.6/73.2/61.2/24.1`，
  而 `README.md` 同口径已是 `78.5/78.2/77.2/65.1/28.8` —— 两份权威文档数字互相矛盾；
- `README.md` 把 C2 第三条判据写成「≤ 2pp」（预注册是 5pp），并把 5 日宽度标成
  「触发否决」（真实淘汰原因是 60 日覆盖率）；
- `docs/specs/2026-10-02-量化引擎口径一致性修正.md` 仍把「方向改评中位数」写成**现状**，
  并引用一个已不存在的测试名；
- `screen.py` 模块文档写「相邻尺度」，代码实现的是「所有 |t|≥1 的尺度同号」；
- `docs/en/architecture.md` 缺 `screen.py` 整行，且有一条不存在的 `--refresh` 命令；
- `test_sync_year_range.py` 用被测常量自身迭代，删键不红。

### 为什么

1. 问题 1/2 是**本轮新引入或新暴露的静默缺陷**：现有守卫全部跑在合成夹具上，
   真数据上必红而合成数据上常绿 —— 正是 `AGENTS.md` 点名的「看着在守、其实什么都没守」。
2. 问题 5 让项目最在意的**预注册纪律在文档层面看起来比代码实际做的更强**。
3. 问题 7 直接踩红线五（时间只在一个时区里流动），而这条红线是两次真实故障逼出来的。
4. 其余是「同一事实两处说法」的分叉，违反「同一事实只保留一个权威来源」。

### 怎么算做完（判据）

每条一条会红的测试，且逐条做过变异验证（改坏必须红）：

1. `test_engine.py::test_observation_on_a_non_trading_day_is_not_dropped` ——
   构造一条日期不在金价日历内的观测，断言下一个日历日引擎拿到的是**它**；
   把 `align_series` 改回 `reindex(calendar)` 必须红。
2. `test_engine.py::test_scenarios_stay_inside_the_interval_when_alpha_saturates` ——
   构造让 α 打到上界的面板，断言 `interval_low ≤ scenario_low ≤ scenario_high ≤ interval_high`
   逐行成立；把 `ACI_ALPHA_CAP` 改回 0.6 必须红。
3. `test_quant_api.py::test_prediction_payload_reports_the_distribution_mode_and_alpha` ——
   接口返回 `distribution_mode` 与 `interval_alpha`；删字段必须红。
4. 同上，接口返回 `expected_capped`；删字段必须红。
5. `test_quant_lab.py::test_the_bench_adjudicates_on_the_forward_window` +
   `test_quant_lab.py::test_a_scale_with_too_few_bets_is_pending_not_failed` ——
   把 `decide()` 改回读 `holdout`、或不传 `effective_sample_size` 必须红。
6. `test_backtest_metrics.py::test_long_horizon_reports_the_normal_fallback_share` ——
   bet 档在 h=250 必须报告退回占比 1.0；删该指标必须红。
7. `test_quant_migration.py::test_migrated_recorded_at_is_converted_to_the_project_timezone` +
   `test_storage_revisions.py::test_created_at_is_written_in_the_project_timezone` ——
   去掉时区换算必须红。
8. `test_quant_migration.py::test_ledger_backfill_fills_only_the_missing_observations` ——
   流水非空但观测缺流水时必须补；改回「全空才补」必须红。
9. `test_screen.py::test_the_screen_thresholds_match_the_preregistered_text` ——
   五个阈值逐值钉住；改任一个必须红。

**能跑证明的命令**：`cd backend && python -m pytest` 全绿；
`cd app && npm run lint && npm test && npm run build` 全绿。

> 安全前提：本机 `backend/.env` 的 `DATABASE_URL` 指向开发库 `gold_analysis`，
> 而 `tests/conftest.py` 会把 `DATABASE_URL` 覆盖成 `GOLDMIND_TEST_DATABASE_URL`
> 或 `sqlite://`。2026-10-02 发生过一次「把该变量指向开发库 → 会话结束 `drop_all`
> 删掉 9 张业务表」的事故。因此本轮所有 pytest 调用都显式带上
> `GOLDMIND_TEST_DATABASE_URL="sqlite://"`。

### 明确不做什么

- 不动因子集、权重、`μ = α + β·score`、方向 = sign(μ)：那是独立的一轮，
  必须先预注册（第二轮 §一 已写死 T1/M1 的判据，等前向窗口）。
- 不把 `MIN_OLS_SAMPLES` / `MIN_ERRORS_FOR_SIGMA` 改成按独立下注折算 ——
  那会改变「哪些尺度发数字」，属于口径变更，必须单独预注册。
- 不动 `docs/specs/2026-10-02-失败率治理.md` 与 `backend/tests/safety.py`
  （同工作区另一处未提交的工作）。
- 不发版、不打 tag、不推远端。

### 怎么回滚

- 代码：`git revert` 本轮的 commit（每个 commit 是一个独立单位）。
- 数据：本轮不改表结构、不删行；问题 7 的换算只影响**新写入**的流水行，
  既有行的 `recorded_at` 不动（换算只发生在迁移脚本里，且可重复执行）。
- 口径：`ACI_ALPHA_CAP` 是常量，回滚代码即回到 0.6。

## 二、方案段

### 1. 不再丢弃非交易日观测（`engine.align_series`）

现在：

```python
reindexed = series.reindex(calendar)      # ← 日历外的标签直接消失
aligned = reindexed.ffill()
```

改为先在**并集**上落位再取日历切片，等价于 `merge_asof(direction="backward")`：

```python
union = series.index.union(calendar)
reindexed = series.reindex(union).ffill().reindex(calendar)
```

`last_real`（新鲜度用的「最近一条真实观测」）仍取**未填充**的那份，避免两遍调用
互相污染。非因子键（`max_age_days=None`）走同一路径，行为不变。

### 2. α 上界与「情景 ⊂ 区间」

`ACI_ALPHA_CAP` 从 0.6 降到 0.5：α/2 ≤ 0.25，区间端点分位必然包含 q25/q75，
嵌套按构造成立。常量旁写明**为什么不能大于 0.5**（否则区间与情景不再嵌套）。

### 3. 名义水平可见（`engine` → `service` → `schemas` → 前端）

`SignalSnapshot` 增加 `interval_alpha` 与 `distribution_mode`（后者已有字段，
补进 payload），`_prediction_payload` 一并输出；前端在「不确定度」旁注明
「名义水平 = 1 − α」与「经验分布 / 正态兜底」。

### 4. 封顶可见

`SignalSnapshot` 增加 `expected_capped: bool`，payload 输出 `expected_capped`；
前端在「期望收益」旁标「已封顶」。

### 5. 研究台与裁决层统一到前向窗口

- `quant_lab.PERIODS` 增加 `"forward"`，`evaluate_periods` 已支持该切片（无需改 backtest）；
- `quant_lab.rule_flags` 传 `effective_sample_size`；
- `decide()` 读 `("candidate", horizon, "forward")`；样本不足时结论是
  `pending`（不可判定）而不是「未过线」；
- 报告抬头、章节标题、候选口径表（`v4` → 按 `MODEL_VERSION` 实值打印）同步。

### 6. 退回占比可见

`backtest._evaluate` 新增 `distribution_mode` 统计：
`distribution_normal_share` / `distribution_empirical_share`（按掩码行算）；
研究台主表新增一列「正态兜底占比」。

### 7. 流水时区统一

- `app/utils/timeutil.py` 新增 `utc_naive_to_local(value)`（把 naive UTC 转成项目时区的 naive）；
- `migrate_quant.ledger_backfill_rows` 的 `LEDGER_INSERT` 改为在 Python 侧逐行换算
  （不再用一条纯 SQL 的 `COALESCE`），并写明假设：`server_default=func.now()` 在
  SQLite 下是 UTC；
- `storage.upsert_series` 显式写 `created_at` / `updated_at`（项目时区），
  让三列共用一个时钟。

### 8. 流水回填按「缺哪些」而不是「是否全空」

`ledger_backfill_rows` 改成返回**缺流水的观测行数**（`factor_observations`
左连接流水表，取 `revision IS NULL`），`apply_migration` 只补这些行。幂等。

### 9. 筛查层阈值守卫

`test_screen.py` 新增一条：把五个阈值与**预注册文本**（`docs/specs/2026-10-02-量化引擎第二轮预注册.md`
§五、`docs/specs/2026-10-02-量化策略提升路线图.md` 的筛查段）逐值对齐，
写法照 `test_quant_lab.py::test_hard_rule_constants_track_the_preregistered_text`。

### 10. 数据与文档小错

- `monitor.RowSpec` 增加 `display_scale`（默认 1.0），`cftc_net_oi_ratio` 用 100 显示成 `%`；
- `sources/gpr.py` 接上 `shift_to_next_trading_day`（与其它后发布源同口径）；
- `sync._missing_reason` 用 `factor_key` 定位到真正相关的源，并把 `skipped` 一并列出；
- 文档同步：`ARCHITECTURE.md` 覆盖率、`README.md` C2 判据与宽度说明、
  `docs/en/architecture.md` 的 `screen.py` 行与假命令、`screen.py` 模块文档、
  `preregistered.py` 的行号引用、口径一致性 spec 的方向口径与测试名。
- `test_sync_year_range.py` 的 yahoo 覆盖判据改成字面量集合，不再用被测常量自证。
