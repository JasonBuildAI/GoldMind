# 计划：预测口径统一

> 任务 → 文件 → 测试点 → commit 边界。按序执行；每一步跑最小检查，收尾跑全档。

1. **spec + plan 落盘**（本文件与同名 spec）
   - commit：`docs: add the single-distribution prediction spec and plan`

2. **引擎与回测：一份分布出口，评同一个方向**（`engine.py`、`backtest.py`、`service.py`、`definitions.py`）
   - 原计划的 2、3 步合并为一次提交：引擎换口径后，回测必须同一次跟上，
     否则中间那个 commit 的测试必然是红的（违反「全绿才提交」）。
   - `build_prediction_frame`：μ 不变；σ 改为走查预测误差（`(forward − μ).shift(h)` 的扩展标准差），
     样本不足时保留「已实现收益扩展标准差」兜底；`probability_up = Φ(μ/σ)`；删掉 `score_probability`。
   - `SignalSnapshot.direction`：改为 sign(μ)，恰为 0 记 `flat`；`_direction_label` 补 `flat → 持平`；
     `MODEL_VERSION=quant-v3`。
   - 回测：命中率、分段、Brier、覆盖率都取 `frame` 的 μ / σ / p_up；新增
     `metrics.score_direction_accuracy`（未校准得分方向的成绩，单列）。
   - 测试：`test_engine.py` 三条判据测试（方向 / 概率 / σ）+ 短历史拒绝出方向，
     `test_backtest.py` / `test_backtest_metrics.py` 判据测试，`test_quant_api.py` 样本门槛随
     可评估窗口（日历 − 2h − 119）重算。四条守卫逐条做变异验证（改坏必红）。
   - commit：`fix: unify direction, probability, uncertainty and scoring on one calibrated distribution`

3. **出口与前端**（`schemas`、`app/src/sections/Quant.tsx`、`api.ts`、`docs/API.md`）
   - 页面新增「因子偏向（未校准）」一行，方向说明改为「漂移 + 因子」
     （`MODEL_VERSION` 与 `flat → 持平` 已随上一步落地）。
   - 测试：`Quant.test.tsx` 扩展；`test_quant_service.py` / `test_quant_api.py` 对齐。
   - commit：`feat: publish the calibrated forecast and the raw factor tilt side by side`

4. **收尾验证**
   - 全档闸门 + 真实数据刷新前后对照 + `gen_api_doc.py --check` + 旧说法全局搜；
   - 结论收进 `docs/00-产品方向.md`、`docs/ARCHITECTURE.md`、`README.md`（如需）。

5. **区间宽度的经验分位校准**（`engine.py`、`backtest.py`、`definitions.py`、
   `docs/00-产品方向.md`、`docs/ARCHITECTURE.md`、本 spec 的落地补记）
   - 动机：统一分布后 80% 名义区间在近 500 个可评估样本只剩 18.4%（250 日）——
     正态分位在误差非正态 / 波动换挡时系统性偏窄。
   - `build_prediction_frame` 在 σ 后追加 `factor = q80(|e|/(z80·σ))`（expanding、无前视）；
     `MODEL_VERSION=quant-v4`；真实数据刷新后重写覆盖率数字。
   - 测试：σ 守卫补 factor 口径 + 新增经验分位校准守卫；两条均做变异验证。
   - commit：`fix: calibrate the interval width to the empirical error quantile`
