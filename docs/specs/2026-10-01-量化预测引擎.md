# 量化预测引擎：以金价四类影响因素为基准的多因子管道

> 本轮改动的 spec。需求段只讲做什么、为什么、怎么算做完；技术从「方案段」开始。
> 落地后的结论以 `README.md`、`docs/ARCHITECTURE.md`、`docs/API.md` 为准；本文件只是这一轮的记录。

- 日期：2026-10-01

## 一、需求段

### 改什么

以「影响国际金价的主要因素」四类框架（货币政策与利率 / 避险与信用 / 供需结构 / 市场与技术面）
为基准，把 GoldMind 的预测从「LLM 读新闻写观点」升级为「实时多因子数据 + 可回测的量化预测」：

1. **实时因子管道**：为四类因素接入真实、免费、无需密钥的数据源（美债名义/实际利率、通胀预期、
   政策预期、美元指数、VIX、信用压力、地缘风险、央行购金、CFTC 持仓、黄金 ETF 份额、动量、
   季节性、比特币、风险偏好），按各自发布节奏自动更新并落库。
2. **量化预测**：用因子面板生成方向性预测（1 / 5 / 20 个交易日），写入 `predictions` 表，
   取代当前恒为空的接口；每个预测带基准价、目标区间、置信度与逐因子贡献。
3. **可验证的准确率**：走查式（walk-forward）回测同一套信号，输出命中率与基准对比
   （永远看多 / 动量 / 抛硬币），把「模型到底准不准」变成页面上可核对的一行数字；
   每次刷新追加一条评估记录，形成准确率的时间序列。
4. **看板呈现**：新增「量化预测」一节：预测结论、准确率、四类因子仪表盘（含来源与数据截至时间），
   任一因子不可用时如实标注。

### 为什么

- 现状的预测没有量化依据：改动前 `docs/ARCHITECTURE.md` 把「预测准确率追踪」列在
  「明确不存在的能力」里，`predictions` 表没有任何代码写入，产品宣称的「价格预测平台」
  是目标而非现状。
- 纯 LLM 新闻总结无法度量、无法回测、无法追责；没有基线可对照，「准确率提高」就无从谈起。
- 图片指出的核心是「各因素权重随周期切换」，这要求数据**持续更新**；
  只靠一条新闻或一次性快照，做不出可验证的预测。

### 怎么算做完（判据）

- **一条会红的测试**：`tests/unit/quant/test_no_lookahead.py` —— 把 t 之后的所有因子数据改成垃圾值，
  再重算 t 时刻的信号，结果必须逐位不变；把实现改坏（滚动窗口改成全样本）必须变红。
- **一条能跑证明的命令**：`cd backend && python -m pytest` 与
  `cd app && npm run build && npm run lint && npm test` 全绿；
  真实回填一次后，`/api/gold/quant/factors` 返回 ≥10 个非不可用因子，
  `/api/gold/quant/accuracy` 返回样本量 ≥500 的命中率与基准对比。
- **页面自检**：量化预测节在全部数据源不可用时显示不可用与原因，不显示任何编造数字。

### 明确不做什么

- 不做实盘交易、不下单、不接券商（沿用 `docs/00-产品方向.md` 第五节）。
- 不引入付费或需要注册密钥的数据源（当前全部数据源均免费且无需密钥）。
- 不做深度学习 / LSTM 预测：10 年日频样本不足以支撑，过拟合风险大于收益；
  本轮的模型是透明、可逐条解释的加权因子组合。
- 不做用户系统、不做个性化。

### 怎么回滚

- 代码：逆序 `git revert` 本轮的 commit。
- 数据：本轮只新增表（`factor_observations`、`model_evaluations`）与 `predictions` 的新增可空列，
  不修改、不删除既有数据；回滚只需停用调度任务并删除新表（见 README「常用命令」中的迁移命令）。

## 二、方案段

### 数据源（全部已在本机实测可用）

| 因子 | 数据源 | 频率 | 发布滞后处理 |
|---|---|---|---|
| 美债 10Y 实际利率 | 美国财政部 real yield curve CSV | 日 | 次日生效（收益曲线收盘后发布） |
| 10Y 通胀预期 | 名义 − 实际（财政部两份 CSV 计算） | 日 | 同上 |
| 政策预期（2Y − EFFR） | 财政部名义 CSV + 纽约联储 EFFR API | 日 | 次日生效 |
| 美元指数 | 东方财富/新浪实时 + Yahoo 历史 | 日 | 当日收盘 |
| VIX | Yahoo Finance | 日 | 当日收盘 |
| 信用压力（HYG/IEF） | Yahoo Finance | 日 | 当日收盘 |
| 地缘风险 | 自有 RSS 新闻语料关键词强度（代理指标，非 GPR 指数） | 每 2 小时 | 当日 |
| 央行购金（中国官方储备） | 新浪财经宏观 API（万盎司） | 月 | 次月 8 日生效 |
| CFTC 投机净多头 | CFTC 公开 Socrata API（合约代码 088691） | 周 | 报告周周二 + 3 个工作日 |
| 黄金 ETF 份额（GLD） | Yahoo Finance（快照，自采集日起积累历史） | 日 | 次日生效 |
| 黄金动量 | Yahoo（GC=F 收盘） | 日 | 当日收盘 |
| 季节性 | 自有价格序列计算（各月历史平均收益） | 日 | 当日收盘 |
| 比特币动量 | Yahoo（BTC-USD） | 日 | 当日收盘 |
| 风险偏好（SPY 动量） | Yahoo（SPY） | 日 | 当日收盘 |

### 数据模型

- `factor_observations(id, factor_key, obs_date, value, source, meta, created_at, updated_at)`，
  唯一约束 `(factor_key, obs_date)`，只存成功观测；失败在快照缓存与 API 中如实报告。
- `predictions` 增加可空列：`direction`、`horizon_days`、`as_of`、`base_price`、`score`、
  `expected_return`、`uncertainty`、`model_version`；`target_price` 继续必填
  （= 基准价 × (1 + 期望收益)）。
- `model_evaluations(id, model_version, horizon_days, window_start, window_end, sample_size,
  accuracy, baseline_up_accuracy, baseline_momentum_accuracy, brier_score, metrics, created_at)`。
- `schema.sql` 同步新增；老库执行 `python scripts/migrate_quant.py`（幂等，只加不删）。

### 信号与回测

- 每个因子做**滚动 z 分数**（窗口 252 交易日，最少 60）：用 t 之前的数据计算均值与标准差，
  窗口内 x 为因子的 20 日变化（利率 / 汇率 / 波动类）或水平值（低频类按最近可得值前向填充）。
- 方向对齐：每个因子带 `sign`（+1 上升利多黄金 / −1 上升利空），`signed_z = sign × z`。
- 合成得分 `score = Σ w_i × signed_z_i / Σ w_i`，仅用当日可用因子；权重只在
  `backend/app/services/quant/definitions.py` 一处定义。
- 概率 `p_up = Φ(score / σ_expanding)`，σ 只用 t 之前的数据。
- 期望收益：扩展窗口 OLS `r_{t→t+h} = α + β·score_t`，样本不足时 β=0（目标价=基准价）；
  不确定度用扩展窗口残差标准差，样本不足时退回已实现波动率。
- 回测：对区间内每个交易日 t 重算信号，比较 `sign(score_t)` 与
  `sign(close_{t+h}/close_t − 1)`，与三个基准对照；同时输出每个因子的单独命中率与 IC。
- 无前视：滚动统计只用 t 之前的数据；宏观因子按发布滞后整体平移；回测在时间上单向推进。

### 接口

- `GET /api/gold/quant/factors?category=` — 因子快照（含状态、来源、截至时间、贡献值）。
- `GET /api/gold/quant/predictions?horizon_days=` — 最新量化预测（方向、概率、目标区间、逐因子贡献）。
- `GET /api/gold/quant/accuracy` — 最新评估 + 历史评估序列。
- `POST /api/gold/quant/refresh` — 手动刷新（抓取 + 重算 + 回测），限流同付费接口。
- 既有 `GET /api/gold/predictions` 改为返回真实数据（保留原字段，新增字段可空）。

### 定时任务（可更新性）

- `update_factors_job`：每 2 小时（`:15`）增量抓取，各数据源按自身节奏跳过未到期的请求。
- `update_quant_prediction_job`：每 2 小时（`:45`）重算预测；每 24 小时追加一次完整回测。
- 两个任务默认开启，可用 `QUANT_ENABLED=false` 关闭。

### 降级

- 单个数据源失败：该因子标记 `unavailable` 并给出原因，其余因子照常计算，权重按可用因子归一。
- 可用因子少于 3 个，或黄金价格序列缺失：返回「预测不可用」，不输出方向与数字。
- 所有外部抓取失败都会被捕获并写入日志，不影响既有接口。

## 三、附：实现中的关键取舍

- **为什么不用 GPR 官方指数**：其发布为 `.xls`，需要新增解析依赖且本机 pip 安装受限；
  地缘风险改用自有 RSS 语料的关键词强度代理，数据同样是真实的、可复核的，且更新更及时。
  文档与界面都明确标注「代理指标」，不冒充 GPR 指数。
- **为什么不做权重学习**：10 年样本训练自由权重必然过拟合；本轮固定权重来自经济机理
  （图片给出的四类框架），并把「每个因子的单独命中率」放进回测结果接受检验。
- **为什么 ETF 用份额而不是持仓吨数**：SPDR / iShares 的持仓 CSV 均已失效或被反爬拦截；
  Yahoo 提供的 GLD 份额是同一需求的真实指标（份额增减 = 申赎 = 资金进出），
  且不需要密钥。历史从采集日开始积累，回测中按可用性参与。
